⛔ No code path connects them: propose_action() only ever drafts a pending proposal. decide_action_proposal() is called only from a separate, distinct UI/API action — never from inside the agent's own tool-calling loop — so no model output, including text copied from a retrieved document, can ever trigger execution. Unchanged since Phase 6; re-verified over real HTTP and via Streamlit's sidebar form in Phase 7, and again in Phase 10's live 7-step demonstration (a real propose → approve → executed cycle).
⚠ Fixed in Phase 10 (was an open scope limit through Phase 8): compare_sources's staleness signal reads document.metadata["status"], which only the Markdown-docs connector populated through Phase 8 — a real, correctly-resolved date conflict between two emails produced no Answer.warnings entry. Phase 10 added the same status vocabulary to the email connector (X-Status header; EMAIL-ACME-301 marked superseded) and strengthened the system prompt so the model still cites a source compare_sources flags as superseded instead of silently dropping it. Verified 2/3 → 3/3 on manual re-runs — improved, not guaranteed, the same reliability caveat as propose_action invocation. Slack remains uncovered by design; no evaluation case currently requires it.

⚠ ./data bind mount is the only persistence boundary: data/raw/ and the reproducible company.db fixture are baked into the image at build time (read-only, by design); the Chroma semantic index, app_state.db (proposals/conversation history/feedback), and generated evaluation results all live under the bind-mounted ./data and survive docker compose down && up. Secrets load only via env_file: .env, never copied into the image. Verified with a simulated clean checkout in Phase 9, not just a successful build.
